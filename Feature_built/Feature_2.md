# Feature 2: OpenAI Customer Support Chat

## Status

Built as a working backend endpoint.

## What is implemented

The chatbot accepts a customer prompt, sends it to OpenAI, and returns a concise
support response.

- Endpoint: `POST /chat`
- Model configured in the current code: `gpt-4o`
- System behavior: acts as a helpful customer-support assistant and answers clearly
  and concisely.
- Request and response bodies are validated with Pydantic models.
- OpenAI failures are returned as HTTP error responses.

## Main source file

- `app/routes/chat.py`

## Request

```http
POST /chat
Content-Type: application/json

{
  "prompt": "Where is my restaurant order?"
}
```

## Response shape

```json
{
  "reply": "The response generated by the customer-support assistant."
}
```

## Required configuration

Set `OPENAI_API_KEY` in `.env` for local development or in the deployment
environment.

## How to verify

Start the API:

```bash
uvicorn app.main:app --reload
```

Then test `POST /chat` from `http://127.0.0.1:8000/docs`.

## Current limitations

- The chat route currently answers from the model directly; it does not retrieve
  stored document chunks before answering.
- It does not preserve conversation history between requests.
- It does not yet use the trained restaurant intent classifier for routing.
- User-facing error messages currently include the exception text and should be
  sanitized before production use.
